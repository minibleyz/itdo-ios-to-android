# AGENTS.md

Инструкции для AI-агентов (Claude и т.п.), работающих с этим репозиторием.

## Подпись коммитов

Каждый коммит, сделанный агентом (не человеком напрямую), должен
заканчиваться подписью-футером в теле commit message:

```
🤖 Committed by AI agent
```

Формат: пустая строка перед подписью, сама подпись — последняя строка
сообщения коммита. Пример:

```
Добавить биометрическую защиту хэша код-пароля

kSecAttrAccessControl(.biometryCurrentSet, .or, .devicePasscode) — ...

🤖 Committed by AI agent
```

Это касается любых правок через API/автоматизацию (create_or_update_file,
push_files и т.п.) — не только правок кода, но и конфигов, CI, доков.

## Версия сборки

При **любом** коммите, меняющем код или конфигурацию приложения (не
чисто-документационные правки вроде README), обязательно поднимать
номер сборки — `CURRENT_PROJECT_VERSION` в `project.yml` — минимум на 1.

`MARKETING_VERSION` (человекочитаемая версия, напр. `1.0.0`) поднимается
отдельно, только по явному решению — не автоматически на каждый коммит.

Пример: было `CURRENT_PROJECT_VERSION: 4` — после следующего
содержательного коммита должно стать `CURRENT_PROJECT_VERSION: 5`, в
том же коммите, что и сама правка (отдельным коммитом на версию — не
нужно).

## Исключение: .github/workflows/

Правки `.github/workflows/*` через API от агента **не проходят** —
GitHub блокирует запись в этот путь без OAuth-скоупа `workflow` у
токена (403 Resource not accessible by integration). Такие правки
вносит только человек напрямую через `git push`. Агент должен явно
сообщить об этом ограничении, а не пытаться обойти его повторными
попытками.
